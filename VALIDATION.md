# Validation of the delivered build

## Desktop release 1.1

The actual packaged `desktop-release/win-unpacked/Wildwood.exe` passed **16 desktop checks**. These covered the standalone window, bundled assets, WebGL, chunk worker, renderer isolation, pointer lock, movement, mouse look, pause, native F11 full screen, mining and pickup, block placement, inventory/crafting, native world export, import, app shutdown, persistent edits/inventory/settings after reopening, and Save & quit. No remote resource requests or renderer/worker errors were recorded. A captured render sample was 131 FPS on this machine.

`npm test -- tests/desktop-assets.test.cjs` passed **14 logic/protocol tests**, including the original 12 game checks and two checks for the desktop asset protocol. The desktop report and screenshots are in `test-results/desktop-packaged/`. Tests used a separate profile and did not modify the player's browser save or regular app profile.

The single-file portable package was generated by electron-builder from the same application. Interactive regression checks ran against the unpacked executable used by the desktop shortcut.

The production build was launched and played through in Microsoft Edge using Playwright, with real pointer lock, mouse movement, key presses, held mouse actions, and interface clicks. Controlled world fixtures isolated physics and combat checks from procedural terrain. Original terrain and day/night scenes were also inspected visually.

- `npm run build`: passed; the game and mesh worker are bundled locally.
- `npm test`: **12 tests passed**.
- `npm run test:browser`: **25 interaction checks passed**.
- Browser JavaScript, shader, worker, and asset error count: **0**.
- The local production server is `server.mjs`; the Windows launcher is `Play Wildwood.cmd`.

The browser checks covered startup, world creation, first-person movement, pointer lock, mouse look, pause, settings persistence, mining with tools and held blocks, ore tool restrictions, placement and inventory consumption, crafting requirements, inventory swapping and shift transfer, collision, jumping, gravity, fall damage, eating, swimming and air, night enemies and sword combat, passive sheep, death/respawn, autosave, export, reload, import validation and restoration, streaming/unloading, and Creative flight/palette/invulnerability.

The core tests additionally cover deterministic generation, cave and ore presence, negative-coordinate chunk edits, cross-border invalidation, spawn safety, atomic crafting under full inventory conditions, raycast faces, outward triangle winding, hidden-face culling, save quota failures, and backup recovery from a corrupt primary save.

During the final 1440 × 900 Edge run, the captured title sample was approximately 144 FPS, and a sample after streaming into a new area was approximately 135 FPS. These are samples on this machine, not a hardware-independent frame-rate guarantee. The streaming check finished with 49 meshed chunks and 81 resident data chunks at a three-chunk view radius, with no generation queue remaining.

Reproducible scripts are in `tests/`. The development folder's `test-results/` contains the full JSON report, screenshots of the title, game, backpack, Creative overlook and night lighting, an exported regression world, and a Playwright trace.

Intentional scope limits are documented in README.md: single player, static voxel water, recipe-based crafting, tools without durability, and simple local steering for creatures.
